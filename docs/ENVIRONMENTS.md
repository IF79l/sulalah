# البيئات

ثلاث بيئات منفصلة تمامًا، لكل منها قاعدة بيانات ومفاتيح وقوالب واتساب خاصة بها (docs/WHATSAPP.md). لا تنتقل بيانات من بيئة لأخرى.

| البيئة             | قاعدة البيانات                                          | الموقع                                 | من يدخلها | البيانات                                               |
| ------------------ | ------------------------------------------------------- | -------------------------------------- | --------- | ------------------------------------------------------ |
| محلي `local`       | Supabase على جهازك (`pnpm db:start`)، أو مفاتيح التجربة | `localhost:3000`                       | المطوّر   | أرقام اختبار برمز ثابت `123456`                        |
| تجربة `staging`    | مشروع Supabase باسم `sulalah-staging` (فرانكفورت)       | معاينات Vercel (كل فرع وكل PR)         | الفريق    | عائلة السهلي التجريبية وأرقام اختبار، بلا رسائل حقيقية |
| إنتاج `production` | منطقة داخل السعودية، تُحدد قبل الإطلاق (انظر أدناه)     | الدومين الرسمي (فرع `main` على Vercel) | الناس     | حقيقية فقط، بلا بيانات تجريبية أبدًا                   |

## كيف يصل التغيير للإنتاج

1. كل فرع وكل PR ينشره Vercel معاينةً على **التجربة** تلقائيًا.
2. الدمج في `main` قرار فيصل وحده. بعده ينشر Vercel الإنتاج.
3. تغييرات قاعدة البيانات (`supabase/migrations`) تُطبَّق على التجربة فور الدمج، ثم تنتظر موافقة فيصل في GitHub قبل الإنتاج (workflow `Database`، بيئة `production` بمراجع إلزامي).

## الإعداد لأول مرة (مرة واحدة)

### أين تُستضاف البيانات

نظام حماية البيانات الشخصية يعدّ الأصل القبلي بيانات حساسة، ومسودة تعديل لائحته (أكتوبر 2026) تجعل الأصل حفظ البيانات داخل المملكة. Supabase ليس له منطقة في الشرق الأوسط حاليًا، فالخطة:

- **التجربة الآن**: Supabase في فرانكفورت `eu-central-1`، بأرقام اختبار وعائلة تجريبية فقط. لا بيانات حقيقية فيها.
- **الإنتاج**: لا نُنشئه قبل قرار الاستضافة (مع رأي المحامي وموقف المسودة). الخيارات: منطقة AWS في السعودية (متوقعة نهاية ديسمبر 2026) عبر Supabase مستضاف ذاتيًا أو دعم رسمي، أو نقل ملفات الشجرة المشفرة إلى منطقة سعودية (مثل Google Cloud الدمام `me-central2`) مع بقاء الحسابات على Supabase. الكود جاهز لهذا: القراءة والحفظ كلها في `apps/web/lib/tree-cloud.ts`.
- **ما لا يخرج من جهاز العائلة مقروءًا**: كل الأسماء والعلاقات، واسم العائلة. الحساب يحفظ الاسم الأول واسم الأب فقط، مع الجوال والاشتراك.

### Supabase

1. أنشئ مشروع `sulalah-staging` في [supabase.com](https://supabase.com)، منطقة Central EU (Frankfurt). مشروع الإنتاج ينتظر قرار الاستضافة أعلاه.
2. **Authentication > Sign In / Providers > Phone**: فعّله.
   - التجربة: أضف أرقام اختبار في **Test Phone Numbers and OTPs** (مثل `966500000001=123456`) بلا رسائل حقيقية.
   - الإنتاج: الرمز يروح على واتساب من رقم سُلالة عبر Send SMS Hook (docs/WHATSAPP.md)، والرسالة النصية احتياط فقط وتحتاج اسم مرسل مسجّلًا لدى هيئة الاتصالات عبر مزود مرخّص (يونيفونك وغيره).
   - أوقف التسجيل بالبريد (**Email > Disable**)، فالدخول بالجوال فقط.
3. خذ من **Project Settings > API Keys**: رابط المشروع و **Publishable key**. المفتاح السري لا يدخل Vercel الآن.

### GitHub (للمايغريشن)

في **Settings > Secrets and variables > Actions**:

- Repository secret: `SUPABASE_ACCESS_TOKEN` (من supabase.com > Account > Access Tokens).
- Repository variables: `STAGING_PROJECT_REF` و `PRODUCTION_PROJECT_REF` (معرف كل مشروع)، و `STAGING_PUBLISHABLE_KEY`، و `STAGING_DEMO_PHONE` (رقم الاختبار).
- Environments: أنشئ `staging` و `production`، وفي كل منهما secret باسم `SUPABASE_DB_PASSWORD` (كلمة مرور قاعدة ذلك المشروع). في `production` فعّل **Required reviewers** وضع فيصل.
- في `staging` أيضًا: `STAGING_DEMO_OTP` (رمز رقم الاختبار) واختياريًا `STAGING_DEMO_TREE_KEY`.

لزرع العائلة التجريبية: **Actions > Database > Run workflow** مع خيار "Plant the sample family on staging". تفتحها بعدها بالدخول برقم التجربة.

### Vercel

1. استورد الريبو، و **Root Directory** = `apps/web`.
2. اربط Supabase من **Integrations** (يضيف مفاتيحه لكل البيئات، ولا بأس).
3. أضف `NEXT_PUBLIC_APP_ENV` = `staging` لبيئة **Preview** فقط. التطبيق لا يشغّل الحسابات والأشجار الحقيقية إلا إذا وجد هذا المتغير، فالإنتاج يبقى نسخة تجريبية في المتصفح حتى لو وصلته المفاتيح، إلى أن نضع له `production` بعد قرار الاستضافة.
4. المفاتيح السرية (`SUPABASE_SERVICE_ROLE_KEY` و `SUPABASE_SECRET_KEY` و `POSTGRES_*`) لا يستخدمها التطبيق، ولا تصل للمتصفح لأن Next.js لا يكشف إلا ما يبدأ بـ `NEXT_PUBLIC_`.
5. في Supabase: **Authentication > URL Configuration**، أضف رابط المعاينات `https://*-khuto.vercel.app`.

## محليًا

```bash
cp .env.example apps/web/.env.local   # ضع مفاتيح التجربة، أو اتركها فارغة للنسخة التجريبية
pnpm dev
```

أو Supabase كامل على جهازك (يحتاج Docker Desktop): `pnpm db:start` يطبع الرابط والمفتاح، و `pnpm db:reset` يعيد القاعدة من المايغريشن. أرقام الدخول المحلية في `supabase/config.toml` برمز `123456`.

`pnpm db:test` يشغّل اختبارات الصلاحيات على أي Postgres يشير له `DATABASE_URL`، وتعمل نفسها في CI.
